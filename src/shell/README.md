# Workspace layout foundation

`WorkspaceLayout` implements the two placements from Kubo's `docs/design/DESIGN-PROPOSAL.md` and the operative `openspec/changes/praxis-shell-modes` amendments. This is an operational application refinement (Operate: variance 3, motion 2, density 7), using Praxis roles on the existing Promethity values and bundled fonts.

The host supplies the existing navigator, header and IPFS `application`, plus one optional `conversation` and its separate live-result `canvas`. `mode` is `application` or `conversation`. The same conversation DOM occupies the assistant column in application mode and the thread column in conversation mode. Never supply two agent roots/controllers, subscriptions or composers to simulate these placements. Slots own their content semantics and localization; the layout adds one main landmark and no fabricated session/history or backend calls.

Inactive application/canvas wrappers use native `hidden`. Their DOM and effects remain mounted so changing placement does not reset selection, restart a run or cancel an ongoing operation. CSS must not override `hidden`. A missing conversation falls back to the IPFS application and does not mount an orphan canvas. Availability and the agent off switch remain the host's responsibility.

`App.js` now mounts `PraxisWorkspace`, which owns one external chat controller for all route/layout views and uses the released host-composed React entry. Home supplies the same controlled composer while its application cell is visible; otherwise the assistant cell supplies it. The transcript cell remains mounted with `showComposer=false`, preserving transcript scroll independently. `applicationInCanvas` places the same application DOM beside the conversation, and full/closed wrappers remain natively hidden. The application wrapper owns its scrolling, so a pane transition does not replace its scroll owner.

New layout defaults to application/closed so a fresh phone visit exposes Home even with chat off; valid saved enum preferences are preserved. Pane/mode controls and editing-safe `[`/`]`, Cmd/Ctrl K shortcuts change placement only. Phone navigation below540px uses the shared accessible More Sheet; ordinary desktop navigation preserves every existing destination and adds Pins/Activity. Search is a composer intent, independent of agent enabled, supported only after the actual index capability probe succeeds. The explicit query handoff is one-shot and generation-bound in memory, never a URL or stored query. The old floating launcher is no longer mounted by App; standalone custom-element delivery remains supported separately.

Trusted `decisionCallbacks` are captured as controller capabilities at initial host mount; `decisions`/`canvas` may render from `{controller,generation}`. Later I/A owners supply actual projections. Current Activity makes no history, count, success or durable receipt claim. These slots do not create authority or another transport/controller.

`workspace.css` uses only the adopted role aliases for colors and inherits fonts. Route padding and Explore overrides remain on the application wrapper; the main landmark retains `data-route`, with phone safe-area clearance supplied by the navigation. No CSS palette, font face, remote resource or motion is introduced.

Authored fixtures cover placement/order, exactly one conversation DOM/subscription, selection/draft retention through controlled mode changes, native hidden boundaries, absent-agent fallback and final unmount cleanup. They have not been run. UI-105's existing final-boundary slots stay pending until the later pane/composer/phone tasks add their real production assertions; these foundation fixtures alone cannot satisfy that oracle. Final browser coverage must exercise real focus exclusion, grid placement and each supported width/theme.
