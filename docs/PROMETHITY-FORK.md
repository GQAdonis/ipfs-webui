# Promethity fork delta

This file maps the structural divergence between this fork (`GQAdonis/ipfs-webui`, product name Promethity) and upstream `ipfs/ipfs-webui`. It exists so that future `git merge upstream/main` runs have every expected conflict already mapped: when upstream touches one of the files listed below, the conflict is expected and this table is the merge guide; a conflict anywhere else is a signal to stop and re-check.

Source: `assessment-ui.md` section 5.8 (phase `agent-backend-settings`), which fixes the strategy. The rebrand is an override layer, not a rewrite:

- New `src/promethity/` folder (`tokens.css`, `fonts.css`, `base.css`, `theme-overrides.css`, `brand.js` constants, logo components) imported last in `src/index.js`. `theme-overrides.css` remaps the ipfs-css/Tachyons colour classes (`.bg-navy`, `.aqua`, `.teal`, `.bg-snow`, `.charcoal`, `.b--*`, and friends) onto Promethity tokens, so the ~163 files using Tachyons classes recolour with zero edits. Override-layer files do not conflict with upstream at all.
- The brand name lives in one constant (`src/promethity/brand.js`) and one Helmet helper, so titles compose as `${t('title')} | ${brand.name}` instead of editing the Transifex-managed locale files.
- Only the files below are structurally edited. Everything else is upstream code under an override layer.

Non-goals (recorded so a merger does not "fix" them): no React 19 / Vite / Tailwind migration of this shell, no rewrite of Tachyons markup across the 163 files, and no edits inside `ipld-explorer-components` (the `/explore` route is themed at the wrapper level only; its internal markup stays upstream and is a known visual seam).

## Everything else

- `src/promethity/**`, `public/fonts/**`, the agent-chat island assets under `public/agent-chat/**`, `src/agent-chat/**` and `src/settings/agent/**` (the Agent settings page, its `SettingsClient` implementations and tests) are fork-only files; upstream never touches them. `public/locales/en/agentSettings.json` is a new `en`-only namespace.
- `public/locales/en/**` carries `en`-only copy edits (`app`, `explore`, `files`, `notify`, `peers`, `settings`, `welcome`: banned words and exclamation marks removed, the product-name uses reworded, the D8 attribution keys added); other locales are Transifex-managed and stay upstream. A translated title that still ends in `| IPFS` is cleaned by `titleWithBrand`.
- `NOTICE.md` is fork-only and sits beside `LICENSE`. `LICENSE` is upstream's MIT text, unchanged; never edit it in a merge.
- `src/promethity/components/**` (the settings primitives: Field, Switch, SegmentedControl, Combobox, StatusLine, ApplyForm/ApplyBar, PolicyDecision) and `src/promethity/icons.js`, `tokens.js`, `page-title.js` are fork-only.
- If an upstream merge conflicts in a file not listed above, treat it as unplanned divergence: check whether the override layer should have absorbed the change before resolving by hand.

## Companion fork: ipfs-desktop (display branding)

The Desktop fork (`tribe-health/ipfs-desktop`) has no delta file of its own, so its display-branding changes are recorded here. `productName` ("IPFS Desktop"), `name`, `appId` (`io.ipfs.desktop`) and every userData path stay as upstream, because Electron derives the userData directory from the app name; `test/unit/display-branding.spec.js` pins this.

| `src/webui/display-name.js` (new) | Exports `displayName` from `package.json`. | Fork-only. |
| `src/webui/index.js`, `src/tray.js` | The Web UI window title and the tray tooltip read `display-name.js` instead of the literal `IPFS Desktop`. | One line each; reapply after a merge. |
